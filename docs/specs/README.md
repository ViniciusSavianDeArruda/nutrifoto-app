# Specs

Especificações de funcionalidades novas ou mudanças significativas no produto.

## Formato

Cada spec é um arquivo `docs/specs/<slug>.md` com:

```
# Título

**Status:** rascunho | aprovada | implementada | descartada
**Data:** YYYY-MM-DD

## Problema

O que está quebrado ou faltando, e por quê importa.

## Solução proposta

O que será feito, em termos de comportamento do usuário.

## Escopo fora

O que explicitamente não entra nesta entrega.

## Contrato de API (se houver mudança)

Endpoints novos ou alterados, com request/response.

## Critérios de aceitação

Lista de comportamentos verificáveis que definem "feito".
```

Specs aprovadas viram trabalho; specs implementadas ficam como registro histórico.
